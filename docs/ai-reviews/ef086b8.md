# ef086b8 — fix: do not reuse a dynamic page cached before login

## What the commit contains

`experimental.staleTimes.dynamic = 0` in `frontend/next.config.ts`.

## Review

The bug was a Transfers server payload fetched before login. After login the nav read the new cookie, and the page body could still be the logged-out payload. Setting the dynamic stale time to 0 makes Next ask for that page again.

This commit does not change auth. `prefetch={false}` on the nav links arrived with the restyle in `0ab5d93`. Both pieces are part of the same fix. The dev server has to be restarted before the config change is picked up.

## Decision

One login is enough. Do not add a second login step to paper over a cached page.
